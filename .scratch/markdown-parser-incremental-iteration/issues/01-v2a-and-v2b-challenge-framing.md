# v2A and v2B challenge framing

**Type:** grilling
**Status:** resolved
**Blocked by:** None - historical decision recorded while charting the map.

## Question

How should the existing v2A and v2B performance targets govern an incremental programme after the all-at-once implementation proved too large and unreliable?

## Answer

v2A is the first challenge and v2B is the final challenge. The existing `5 ms`, relative `2x`, and allocation-reduction goals remain challenge metrics rather than promises that justify an overall rewrite. Each module refactor must first demonstrate an independent result; only evidence from v2A determines the eligible scope and metrics of v2B.
